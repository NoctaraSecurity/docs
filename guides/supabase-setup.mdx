---
title: "Supabase setup"
description: "Configure database schema, RLS, storage buckets, and realtime."
---

Noctara depends on Supabase for auth, PostgreSQL, storage, and realtime events.

## 1. Run migrations in order

Run each SQL file from `supabase/migrations/` in numeric order.

Required sequence:

1. `001_initial_schema.sql`
2. `002_rls_policies.sql`
3. `003_storage_setup.sql`
4. `004_webhook_function.sql`
5. `005_project_restructure.sql`
6. `006_add_structured_summary_and_cve_fields.sql`
7. `007_token_billing_system.sql`
8. `008_fix_token_transactions_rls.sql`
9. `009_allow_active_code_select.sql`
10. `010_add_uploads_delete_policy.sql`
11. `011_company_context_wizard.sql`
12. `012_company_assets_storage.sql`
13. `013_add_company_to_uploads.sql`

## 2. Verify buckets

- `log-files` (private): upload artifacts
- `company-assets` (private): company logos/docs/policies

## 3. Confirm RLS

RLS should be enabled on core tables, including:

- `profiles`, `projects`, `uploads`, `report_blocks`
- `token_transactions`, `redemption_codes`, `code_redemptions`
- `companies`, `cve_cache`

## 4. Enable replication for realtime UX

In Supabase, enable replication for tables used by realtime subscriptions:

- `uploads`
- `report_blocks`
- `profiles` (optional but useful for live token balance)

## 5. Configure API keys

In `.env.dev`:

- `SUPABASE_URL`
- `SUPABASE_SERVICE_KEY`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`

The engine uses service role credentials. The frontend uses anon key credentials and relies on RLS.
